### 架构与模块职责

本次只有版本输入和直接 Interface 差量，没有新的系统流程或依赖方向。现有结构保持如下：

| Module | Interface 与 Seam | 设计结论 |
|:-------|:------------------|:---------|
| `CodexAppServerAdapter`（`src/adapter.ts`） | DSH `LlmAdapter` seam；调用者只提供 `GenerateOptions`，适配器拥有历史、图片、工具和重放投影 | 继续复用；`options.system ?? ''`、图片能力肯定检查、工具命名空间和缓存 epoch 不移动 owner |
| `CodexAppServerRunner`（`src/runner.ts`） | `CodexAppServerRunnerPort` 与 DSH `SubprocessHandle` seam；Runner 拥有 JSON-RPC、握手、线程和完整进程树清理 | 只改版本常量；`terminate`、`waitForExit`、`done` 的生命周期 Interface 保持不变 |
| 浏览器 Assistant renderer（`src/client/index.ts`） | DSH `assistant-step` slot、`PropsRuntime` 和 `conversation.message.images` renderer seam | 继续使用当前 slot；仅当 rc1 编译或客户端测试直接命中时修既有调用点 |

`codebase-design` 结论为 `pass`：这三个 Module 都是已有深 Module，接口学习面小而实现和测试面集中；一次 Adapter、一次 Runner seam 和一个客户端 slot 已经提供足够 leverage、locality 与 testability。删除差量不会消除任何重复实现，因此不新增 facade、registry、slot 或第二适配器。

### 接口、数据与状态

- rc1 静态 Interface 差量中 `GenerateOptions.system` 仍可选，生产代码已有空字符串归一化；`Chat.openFile` 的可选行号不是当前调用点；`SubprocessHandle.pid` 被移除，只影响 runner 测试夹具。
- 运行时数据流不变：`initialize` 身份确认 → `thread/start` → `turn/*` → 事件映射；失败仍按 `PROTOCOL_VERSION`、`TRANSPORT`、`MALFORMED_RESPONSE` 等既有 `LlmError` code 表达。
- Session、附件 marker、重放 version `4`、工具 callback 和临时目录的 owner/状态机不变；版本号进入既有 cache epoch，版本变化自然触发冷重建。
