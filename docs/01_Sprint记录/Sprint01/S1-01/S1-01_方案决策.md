# S1-01 方案决策：升级 DSH 依赖并支持 Codex 0.154

> 方案版本：`S1-01-SD-v1`（正式方案，已批准）
> 批准帧：`S1-01-APPROVAL-v1`；批准收据：`S1-01|S1-01-SD-v1|S1-01-APPROVAL-v1`
> 决策项：`S1-01-SOL-01`
> 形式：`keep_single`（一个依赖兼容交付结果）

## 1. 决策结论

采用 `S1-01-SOL-01`：将插件的 DSH 依赖族整体对齐到规范版本 `0.1.5-rc.1`，将 Codex CLI 与 App Server 运行时固定到 `0.154.0`，沿用当前 `ctx.llm`、`SubprocessHandle` 和浏览器 slot 的既有 Module/Interface/Seam；以编译、单元/线协议、构建打包和有登录条件的真实 App Server 烟测证明兼容性。

登记原话中的 DSH `0.1.5-rc1` 按可核验的 semver 规范化为 `0.1.5-rc.1`：目标父仓库 tag、各 DSH 包清单和可解析的 npm 版本均使用带点写法，`@deepseek-ai/dsh-llm@0.1.5-rc1` 没有可解析版本。Codex `0.154` 规范化为 npm 可解析的精确版本 `0.154.0`。

本阶段已将批准的方案物化为正式方案和阶段总结，并按批准帧执行精确提交。插件自身 `package.json` 的发布版本保持当前值，发布 tag、推送、合并和用户验收由其他阶段负责。

## 7. To-spec 规格摘要

### Problem Statement

插件当前声明 DSH `0.1.3-alpha.1`、Codex `0.153.3`，而目标运行图已进入 DSH `0.1.5-rc.1` 与 Codex `0.154.0`；仅改版本字符串无法证明 App Server、客户端 Interface 和锁/CI 图兼容。

### Solution

以现有 Module/Interface/Seam 为基线，整体更新 DSH 依赖族和 Codex exact pin，锁定可重现的 rc1 DSH 源，校准运行时握手和版本敏感文档，并用分层测试和有界真实烟测闭合安装到 App Server 的路径。

### User Stories

1. 作为 dsh-plugin-codex 维护者，我希望插件能在 DSH `0.1.5-rc.1` 和 Codex `0.154.0` 的运行图中安装、构建并完成现有 Codex provider 流程，以便继续使用当前的模型、工具、图片、Session 和浏览器能力。

### Implementation Decisions

- DSH 运行时依赖采用同一 rc1 家族，避免 peer 与本地 link 图分裂。
- Codex 采用 `0.154.0` exact pin，并让运行时 user-agent 检查与 package/CI/lock 同源。
- 沿用 `LlmAdapter`、`SubprocessHandle` 和 `assistant-step` slot 的既有 Interface；只收敛直接证实的 rc1 差量。
- 模型目录继续是静态、可审计的配置；每次 Codex pin 变化先以真实 `model/list` 证据校准，不引入额外动态服务。

### Testing Decisions

- 只测外部行为：版本解析、安装图、运行时握手、模型目录真实性、现有协议/回放/工具/图片/Session/客户端行为和打包表面。
- 复用现有 Vitest unit/wire/client/e2e 入口；真实 e2e 依赖本地 Codex 登录并独立标记环境缺口。

### Out of Scope

插件自身 release 版本、远程仓库操作、父仓库修改、全库重构、新架构/ADR、动态模型服务和未由编译/协议证据触发的功能变化。

### Further Notes

`0.1.5-rc1` 是登记时的用户术语；实施和 lockfile 必须使用可解析的 `0.1.5-rc.1`。所有运行时声明仍保留原有安全策略、资源清理和账户边界。
