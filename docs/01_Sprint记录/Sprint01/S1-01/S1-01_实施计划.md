## 3. 验证与恢复顺序

1. 读取父仓库 rc1 tag/commit 与工作树状态；父仓库只允许生成构建产物，保留用户未跟踪预研文档；若父仓库 root 聚合入口自身失败，保留失败签名，并以当前项目实际消费的 linked package 产物与下游门禁作为插件范围证据。
2. 修改 package/workspace 声明，使用包管理器重新生成 lockfile，随后以 frozen install 复核同一图。
3. 修改 Runner 常量和直接命中的 mock；先跑 typecheck、Runner/wire/client 聚焦测试，再跑完整 unit suite。
4. 用 Codex `0.154.0` 执行 `initialize` + `model/list`（`includeHidden=false`,`limit=100`），只按真实目录证据同步 `src/index.ts` 与版本文档。
5. 跑生产 build、package verify、check；具备登录时在兼容配置 home 跑既有 `tests/real-codex.e2e.ts`，默认 home 的配置失败必须单独保留，不与兼容 home 结果合并。
6. 以当前 changed paths、AC 和失败签名生成实施总结、测试报告和检查单；插件范围相关回归通过、仅外部聚合构建或本地配置遗留时可交接 `partial_with_legacy`，不得把遗留签名改写为通过。

恢复规则：npm/lock 失败从 package 输入和同一方案版本恢复；父仓库声明缺失先构建 rc1；TypeScript/测试失败只修直接 Interface 差量；协议长期语义变化回交 `solution-decision`；登录或外部服务不足只保留 `unverified` 证据；不执行 reset、清理、跨仓库恢复、发布或合并。
